# Repository hygiene

Call `.github/workflows/repo-hygiene.yml` at an immutable commit with the same
`hygiene-revision` input, on `pull_request` and `merge_group`. Require the
`repo-hygiene / repo-hygiene` check (caller job / reusable job) in branch rules.
This public, small workflow needs only `contents: read` and no paid service.

Ordinary PR events report the required check as skipped before a runner is
assigned. The reusable leaf carries the condition so the nested required check
name stays identical. Real hygiene runs in the merge queue, on explicit
manual/full-ci requests, and on direct pushes to the default branch. Pushes by
`github-merge-queue[bot]` skip duplicate validation after a successful queue run.

`python3 scripts/repo_hygiene.py --staged` runs offline in hooks;
`--base BASE --head HEAD` scans every commit in a PR, including blobs later
removed, including every merge against each parent, and the final range diff. Gitleaks scans the commit
range or staged index, using upstream default rules with redacted output.
Repository config, inline suppressions and environment overrides are ignored.
Secret detection has no path exceptions.

CI also checks the author AND committer of every commit in `BASE..HEAD`, including
intermediate and merge commits, through the GitHub commit API using the read-only
Actions token. Each email must resolve to a GitHub account. GitHub bots (including
`github-actions`, `dependabot` and accounts ending in `[bot]`) are accepted through
their GitHub login; a bot-looking display name alone does not establish identity.
Unregistered legacy identities need an exact email and reason under `identities:`
in the committed `.repo-hygiene-allow`, for example:

```text
identities:
  legacy@example.org	Published historical contributor
```

Entries remain TAB-separated; identity wildcards are rejected. A `paths:` section
can resume path allowances after `identities:`. Existing unsectioned path entries
remain valid. Review identity exceptions alongside the commits they authorize.
API failures fail the CI check. Offline range checks inspect blobs and secrets;
add `--github-repository OWNER/REPO` with `GITHUB_TOKEN` to verify identities too.
The staged local check stays offline and only warns when the effective author or
committer email differs from `git config user.email`; it does not block that case.

Each added/modified file blob must be at most 1 MiB. Data/archive/document types
require an explicit fixture allowance. Unique, non-exempt added blob bytes sum
to at most 5 MiB per PR (or staged change); repeated copies of the same blob
count once. Modified files count at their full new size. Historic, unchanged
files are not charged. A rename is inspected as an addition.

Shared exceptions come from the committed head (or staged index) file
`.repo-hygiene-allow`: repository-relative glob, TAB, one-line reason. Blank
lines and `#` comments are accepted. Review allowances as part of the PR.
For example, `tests/fixtures/**` followed by a TAB and
`Synthetic inputs generated by tests/make_fixture.py`.
Only synthetic or published data belong in fixtures. Never commit non-public
machine/experiment or collaborator data (ITER/TC24/IMAS, AUG shots, JT-60SA).
Keep campaign outputs outside Git, with checksums and a recorded location.

For staged checks in external repositories, keep local path exceptions in
`$(git rev-parse --git-common-dir)/info/repo-hygiene-allow`. This file is shared
by the repository’s worktrees and stays outside commits. Use `glob<TAB>reason`,
as in `.repo-hygiene-allow`; absolute patterns, missing reasons and `identities:`
sections are rejected. Range and CI checks ignore this file, and its rules never
waive secret detection.

Heavy CI runs only in public repositories. Private repositories validate via
cluster jobs recorded in the PR; GitHub Free cannot enforce private rulesets.
