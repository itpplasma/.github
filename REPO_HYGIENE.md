# Repository hygiene

Call `.github/workflows/repo-hygiene.yml` at an immutable commit with the same
`hygiene-revision` input, on `pull_request` and `merge_group`. Require the
`repo-hygiene / repo-hygiene` check (caller job / reusable job) in branch rules.
This public, small workflow needs only `contents: read` and no paid service.

`python3 scripts/repo_hygiene.py --staged` runs offline in hooks;
`--base BASE --head HEAD` scans every commit in a PR, including blobs later
removed, and the final diff for merge resolutions. Gitleaks scans the commit
range or staged index, using upstream default rules with redacted output.
Repository config, inline suppressions and environment overrides are ignored.
Secret detection has no path exceptions.

Each added/modified file blob must be at most 1 MiB. Data/archive/document types
require an explicit fixture allowance. Unique, non-exempt added blob bytes sum
to at most 5 MiB per PR (or staged change); repeated copies of the same blob
count once. Modified files count at their full new size. Historic, unchanged
files are not charged. A rename is inspected as an addition.

Exceptions come only from the committed head (or staged index) file
`.repo-hygiene-allow`: repository-relative glob, TAB, one-line reason. Blank
lines and `#` comments are accepted. Review allowances as part of the PR.
For example, `tests/fixtures/**` followed by a TAB and
`Synthetic inputs generated by tests/make_fixture.py`.
Only synthetic or published data belong in fixtures. Never commit non-public
machine/experiment or collaborator data (ITER/TC24/IMAS, AUG shots, JT-60SA).
Keep campaign outputs outside Git, with checksums and a recorded location.

Heavy CI runs only in public repositories. Private repositories validate via
cluster jobs recorded in the PR; GitHub Free cannot enforce private rulesets.
